# Tests

Everything here runs on a Linux PC, without an iPod and without root. Nothing is downloaded; all test data (music
files, covers, the library) is generated by the scripts.

```sh
tests/run_tests.sh          # full engine suite (about 15 s); "quick" skips the failure and crash sweeps
tests/test_scripts.sh       # install / update / remove scripts on a FAT32 image
```

Needs: `gcc`, `python3` (standard library only); for `test_scripts.sh` also `mtools` and `dosfstools`.

## How it works

- `build_sim.sh` compiles `ns_sim`: the real `src/ns_engine.c` and `src/ns_art.c` with the platform layer in `ns_host.c`, which
  maps the iPod file system onto a directory tree and can inject faults (write errors, crashes at the N-th operation, a
  corrupted write, a low battery, and the device's I/O restrictions with `NS_SDK=1`).
- `nsfix.c` builds a small synthetic, signed library (one track "Fixture" by "Test Artist") and verifies signatures.
  `sqlcheck.py` opens the SQLite files with Python's `sqlite3` and runs `integrity_check`.
- `mkmp3.py` generates silent MP3 files with ID3v2.3 tags and embedded synthetic covers (baseline and progressive JPEG,
  PNG, oversized tag).

## What `run_tests.sh` checks

| Test | Checks |
|---|---|
| T1 | import of 4 files + junk: signature/cbk/SQLite valid, 5 tracks, byte-identical copies, sources removed, ArtworkDB and `.ithmb` sizes, `.bak` equal to the original |
| T2 / T3 | dry run changes nothing; the first run is a dry run |
| T4 | `noart.txt` skips covers |
| T5 / T6 | invalid library signature and low battery: nothing is written |
| T7 | oversized ID3 tag is refused per file |
| T8 / T9 | device I/O semantics; a second import appends covers |
| T10 | write errors injected at 23 points: the library is always valid, restored to the original on failure |
| T11 | process killed at ~64 points, then restarted: always a valid library, no journal left |

`tests/test_scripts.sh` covers install, rollback after an injected failure, update (idempotent, with rollback), remove, slot
detection and the refusals.

The `NS_SIM_GUID` environment variable (default `0123456789ABCDEF`, a test value) is the signature key used by the simulator.
